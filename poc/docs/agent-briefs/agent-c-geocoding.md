## Scope

Prove `"Dizengoff Center"` becomes `32.075…, 34.774…` and `"HaShalom Station"` resolves to
the right place. PRD §10's PASS bar is **≥20 of the corpus resolving correctly enough to
start routing**. The corpus is 100 so the per-category breakdown is meaningful — a bare
pass/fail count would waste it.

## Environment

MOTIS v2.11.2 is already running and healthy on **port 58080** (`docker ps` → `poc-motis`).
Agent B built the graph and fixed a healthcheck that reported `unhealthy` while serving
fine — `localhost` resolves to `::1` in that image and MOTIS binds IPv4 only. Use
`127.0.0.1:58080`, not `localhost`.

Do not rebuild the graph. Do not restart the container unless it is actually broken.

## What to do

Run all 100 queries in `poc/corpora/places.json` against MOTIS geocoding. Score each
against `expect.lat/lon` within `expect.tol_m`.

Report hit rate **per category**, not just overall:

`station`, `poi_university`, `poi_hospital`, `poi_mall`, `poi_landmark`, `address`,
`neighborhood`, `misspelling`, `translit`, `near_dependent`

Also split by `lang` (he / en), because Hebrew-vs-English performance is the single most
important axis for an Israeli planner and an aggregate number hides it.

### The `near` cases are the interesting ones

P095–P100 carry a `near` bias point. **P095/P096 are the same query string with different
correct answers** ("Central Station" near Tel Aviv vs near Jerusalem), as are P097/P098
("Herzl"). An engine that ignores `near` cannot pass both halves of either pair. Report
those pairs explicitly — passing one and failing its twin is the signature of a geocoder
that is not using the bias point at all.

### Corpus caveats you must respect

- Coordinates are hand-entered and were **already wrong once**. P011/P012 (Ben Gurion
  Airport) were corrected on 4 Sep from GTFS stop 10971 after being 1,961 m out.
  If a query fails and you can show the corpus coordinate is the thing that is wrong,
  **say so and prove it against the feed** — do not quietly relax the tolerance.
- Corrections belong in `poc/corpora/build_places.py`, the generator, then regenerate.
  Never hand-edit `places.json`.
- KDP-010 warns that a stop named after a railway station is usually the *bus stop
  outside it*. Expect this to bite the `station` category and report it rather than
  absorbing it.

### Nominatim

Bounded comparison only, ≤1 request/second, no autocomplete (PRD §10). Optional. If you
use it, it is evidence about *relative* quality, never ground truth.

## Deliverables

- `poc/geocoding/` — the runner and scorer
- `poc/results/poc-5.json`
- `poc/results/places-h4-review.md` — the human review sheet for checkpoint H4: every
  query, what came back, whether it scored, and a blank verdict line for the ones where
  "correct enough to start routing" is a judgment rather than a distance.

### Result schema

```json
{
  "poc": 5,
  "name": "Address and place search",
  "status": "PASS | PARTIAL | FAIL",
  "generated": "ISO date",
  "headline": "one line for the status table",
  "feed_sha256": "from manifest.json",
  "capabilities": { "resolve_places": true },
  "metrics": {
    "overall": { "correct": 0, "total": 100, "prd_bar": 20, "meets_prd_bar": true },
    "by_category": { "station": { "correct": 0, "total": 20 } },
    "by_lang": { "he": { "correct": 0, "total": 0 }, "en": { "correct": 0, "total": 0 } },
    "near_pairs": { "P095_P096": "both | one | neither", "P097_P098": "both | one | neither" },
    "latency_ms": { "p50": 0, "p95": 0 }
  },
  "cases": [
    { "id": "P001", "query": "...", "returned": "...", "lat": 0, "lon": 0,
      "distance_m": 0, "tol_m": 400, "scored": "pass | fail", "note": "" }
  ],
  "failure_modes": [
    { "mode": "short description", "count": 0, "examples": ["P0xx"] }
  ],
  "notes": []
}
```

`failure_modes` ranked by count is the most useful thing you produce — it is what tells the
developer whether Phase 1 needs Photon, and for which query classes.

## Rules

- **Never write a capability `true` that a test did not demonstrate.**
- ≥20 correct meets PRD §10's bar, but "correct enough to start routing" is ultimately
  checkpoint H4. If the count passes while the failure modes look serious, say so in
  `headline` and set `status` to `PARTIAL`.
- Append genuinely new data findings to `poc/docs/known-data-problems.md` as KDP-012
  onward, matching the existing format: what, evidence with the feed hash, why it matters,
  action.
- Use `python` (not python3) on this machine.
